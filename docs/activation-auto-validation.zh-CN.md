# 工具激活时序的自动沙箱验证

本模块把“激活工具后何时可以调用”接入自动评测链路。只验证本地无副作用夹具；不授予文件、网络、账号、付费生成或生产操作权限。`autoLearning` 中该域固定为 `evaluationOnly:true`，不会进入正式任务，即使全局冻结日后变化也不自动晋升。自动验证完成不等于解除冻结，也不等于候选已经产生可用收益。[日常受限提示](daily-experience.zh-CN.md)是另一个需显式启用的通道，不能混用两者的批准或结果。

## 题目与边界

固定题库位于 `packages/mnemo/fixtures/activation-timing-corpus.json`。其中两题用于开发，七题用于预先锁定的配对机制观察，三题检查边界。

| 分层 | 内容 | 用途 |
| --- | --- | --- |
| development | 求和、计数 | 检查模型接口、真实工具绑定与答案判定；不并入正式收益统计 |
| heldout | 净合计、最大值、最小值、数字排序、键值查询、文本连接、字符码校验 | 检查新任务中真实调用与结果交付 |
| guard | 已激活、权限禁止、合同元数据未知 | 检查经验是否被过度套用、权限是否被绕过、原有能力是否退化 |

这些是同一激活错误机制下的不同操作内容与边界，不是十二个独立机制。最大值与最小值等题也存在明显相关性。公开题库不能被长期视为模型从未见过的保留集；部署者应在运行前记录曝光历史，重复运行只能算回归，不能重新声称首次保留验证。

旧 `experiments/activation-timing/` 的任务和结果属于历史协议。历史题可以做回归，但不能改名字后重新算作本轮独立保留题。开发中查看过某题的模型结果、据此修过提示词或判定器后，该题也不能继续算未曝光保留题。

## 什么才算真实验证

题库只是输入和标准答案。只有使用实际宿主 ToolRuntime 的绑定、激活与下一步提示组装，加上实际配置模型产生的程序，留下原生工具执行轨迹，才属于真实模型沙箱运行。脚本预先写死“先激活再调用”、模拟模型响应、单元测试通过或模型自述，均不能代替这项证据。

每题的 baseline 和 candidate 使用独立新宿主与独立对话。两臂只在是否提供条件经验上不同，工具、权限、合同、模型路由、请求预算与判定器相同。目标工具只读取预置夹具，参数为空对象，计算确定的 JSON 值；不接触业务文件或外部服务。标准答案不发送给模型，模型必须通过真实工具取得结果，猜中答案不能代替实际成功调用。

未激活匹配组按真实宿主处理程序开始时的工具绑定；不能在验证器中强迫模型先激活、强迫等待，或提前修正它的程序。已激活组不应无故退化。权限禁止组必须没有目标工具实际执行，并明确报告权限限制；若发生被守卫拒绝的调用尝试，应单独记录，不算权限绕过成功。合同未知组只是隐藏合同元数据，不能当成已经验证另一种宿主时序合同。

## 冻结、预算与结果

运行前固定候选 packet、题目、标准答案、模板、运行器、真实 runtime 依赖、模型路由、分组与预算的摘要。每臂最多六次模型请求；错误、取消、中止、预算耗尽和未开始的实验臂都要留下，不以删除失败或挑选重跑结果提高收益。

实际请求可以产生正常模型推理费用；本沙箱不包含图片或视频生成接口，也不提交付费生成。公共题库和文档不包含模型名称、凭据、账号或服务器路径；运行身份与完整原始轨迹保存在部署者私有目录。

至少报告任务完成、真实目标调用、同程序激活后缺绑定错误、重复错误、权限越界、请求次数与缺失结果。成功结果必须由工具事件和最终答案共同支持。调用失败应区分模型错误、宿主执行错误与提供商故障；这些结果不能冒充经验有效。

本题库只有七个正式任务分层和三个守卫，不满足现有自动吸收的至少六十个独立任务与正收益下界要求。不能为通过门槛复制题目、换工具名、换数字或降低收益门。即使沙箱所有任务都做对，若 baseline 同样做对，也只能说明未测出收益。

因此，这条链路支持“候选 → 自动验证 → 原始证据 → 不确定/待审结果”，同时保持 `frozen`。`insufficient-benefit` 是符合证据强度的结论，不是需要消除的报错。当前激活域只限沙箱评测，不能注入正式任务或写入原长期记忆；未来若设计推广路径，还须单独审查机制与独立证据，不能沿用本轮结果自动放行。

## 推理诊断与重新评测

每次沙箱推理都记录有界的结束类型、用量、调用方 token/超时上限和本地推理 ID。用量来自官方独立 `usage` 事件，保留最后有效累计快照，不叠加；未提供的字段保持未知。`max-tokens`、提供方错误、取消和缺失结束事件均不能作为正常完成。错误记录只保存固定分类、HTTP 状态、重试等待和请求 ID 摘要，不保存提供方原始消息、凭据或提示词。请求记录的摘要另写入运行收据。

可信操作方可在工具激活机制的政策中设置 `inferenceBudget: {"maxTokens": 3200, "timeoutMs": 60000}`。缺省仍为 1600 token、30000 毫秒；允许范围分别为 1600–6400 和 30000–90000，必须同时提供两个字段。它们是调用方上限，SDK 可能按上下文窗口收紧，不能冒称提供方实际收到的参数。任务输入和模型回复不能修改这些值。预算、政策、模型路由、题库与运行器身份均进入冻结协议摘要。

失败后不覆盖原评测，不退款已预留额度，不清除题目曝光。新的协议与预算生成独立条目；使用已曝光题目时标记 `regression-replay`。诊断请求必须单独记账；即使修复后完整执行，相关机制题也不因此成为统计独立样本，不能解除冻结或写入长期记忆。

已确认的模型 token 截断属于该实验臂在既定预算内失败：仅当可信适配器返回固定的非正常结束代码、`finishKind=max-tokens`，且没有取消或提供方故障标记时，记为 `model-token-budget-exhausted`、`success=false`。保留失败请求、用量和收据，不解析或执行截断文本，不重试该臂，再测后续独立实验臂。这不算任务成功，也不自动解除冻结。传输故障、超时、未知结束、来源/政策变化、权限或沙箱清理异常仍中止整轮；旧轮的中止记录不会按新协议回写。
