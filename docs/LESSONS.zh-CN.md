# 宿主驱动的经验提炼与复用

`lessons` 是 MNEMO 的可选通道，默认关闭。它从执行过程提炼带来源和适用条件的经验，在同类错误或任务开始时按需注入；执行任务的模型不必主动调用记忆工具。它不训练模型权重，也不把所有失败正文直接写入普通长期记忆。

## 执行链路与准入范围

普通工具和 PTC 子调用按调用 ID 关联、去重。回合结束后，符合门槛的证据进入有预算的提炼队列。证据先脱敏再截断，最终请求重新检查预算，避免拼接反馈后超限。

当前自动验证只支持两个明确契约：编辑目标之前需要读取；文件读取后发生变化时需要重新读取。验证器要求同一目标依次存在编辑失败、读取成功、编辑成功，且没有随后再次失败。通过后使用验证器的固定建议，模型生成的自由文本不会直接变成已验证规则。

其他踩坑、修复和成功方法可以形成 `candidate`，交给人工审查。重复出现、模型置信度、自由文本合并或调用成功次数都不能代替验证。成功方法不参与错误后的召回；任务开头是否注入由独立配置控制。

状态为 `candidate`、`active`、`suspended`、`retired`。人工停用优先：并发提炼、外部写入、类型变化和过期整理不能撤销人工决定。工具级经验通常只在原项目使用，获得更多项目证据或经过明确审核的种子另有共享规则。

插件关闭或失去写入权限后，等待中的模型结果不能再提交到经验库。调用前在仍有权限时持久预留预算并移出该队列项，保存失败不会发请求，重启不会自动重放已预留的调用。若预留后、发出请求前权限改变，该次保守预留可能没有实际费用，不能用账本计数代替服务商账单。

## 安装与启用

按主 README 安装整个 `packages/mnemo`，保留全部 `lib/lessons*.js`。不要只复制入口文件。SDK 和配套插件版本要求与主仓库一致。

在该插件的宿主配置下显式增加：

```yaml
lessons:
  enabled: true
  injectOpening: false
  injectOnError: true
  maxCallsPerDay: 20
  idleMs: 600000
```

这是一份保守的配置示例，不会被安装脚本自动写入已有实例。默认按来源会话的模型路由提炼；需要固定提炼器时，可自行配置 `lessons.extractor.provider` 和 `lessons.extractor.model`，凭据仍由宿主管理。调用会消耗模型额度，应自行设置预算。

通过宿主支持的插件管理/重新加载流程应用配置，避免启动第二个连接相同数据目录的实例。停用时设置 `lessons.enabled: false`，无需删除经验库或退回旧版本。

`lessons` 与原有 `executionExperience`、`autoLearning`、`dailyLearning` 和 `successfulExperiences` 独立。旧记忆的 `frozen` 不是 lessons 的停用开关；显式启用 lessons 也不解除旧冻结。`lessons.exclusive: true` 只关闭旧 successfulExperiences 通道，并不关闭其他通道，应按实际配置判断是否重复采集。

## 观察与人工审查

插件 `report()` 的 `lessons` 部分提供状态计数、队列、提炼/注入/错误和日调用数；`legacy` 列出仍运行的旧通道。持久数据位于 MNEMO 配置数据目录下的 `lessons/`，独立于普通记忆账本。

以下命令从 `packages/mnemo` 执行，目录由部署者指定：

```bash
node tools/report.mjs "$MEMORY_DATA_ROOT/lessons"
node tools/audit-sample.mjs sample --dir "$MEMORY_DATA_ROOT/lessons" --out audit.md
```

审查文件会列出全部需人工处理的候选及随机抽检项。勾选 `approve` 表示批准候选生效，勾选 `retire` 表示停用；确认后再执行：

```bash
node tools/audit-sample.mjs apply audit.md --dir "$MEMORY_DATA_ROOT/lessons"
```

这些操作在写锁下重新读盘，并保留人工状态的版本与来源。不要直接用旧 JSON 覆盖正在使用的账本。

仓库种子文件为空，不含任何部署者的历史经验。若确需手工导入自行审查的种子，准备自己的文件并逐条明确设置 `approved: true`；缺省、false 或其他值均不会导入：

```bash
node import-seeds.mjs ./reviewed-seeds.json "$MEMORY_DATA_ROOT/lessons"
```

导入和人工审查属于显式数据操作，普通源码升级不会自动执行。

离线历史采集工具需要部署者明确指定已授权的归档目录。`p0-evidence` 和 `p0-signatures` 在归一化和截断前先脱敏；输出仍是本地诊断资料，不应直接上传公开仓库。`p0-batch` 需要自行提供模型 adapter：`--limit` 限制提案条数，`--max-calls` 独立限制请求次数（省略时等于 limit），失败和空响应也计数，无自动重试；所有提案默认未批准。

## 测试与评估

MNEMO 正式回归测试与专用复跑脚本已移除。清理前的部署候选曾在独立环境完成 **901/901，通过 901、失败 0、取消 0、跳过 0**；该结果只作为历史摘要，不代表当前公开源码树仍可执行同一测试套件。产品的经验提炼、人工审查与运行时契约验证未因此删除。

离线评估入口为 `packages/mnemo/eval/run.mjs`，评估包含项目约束的库必须传入准确的 `--scope`。评测采用生产注入生命周期、禁记判断和状态规则，记录实际注入量，不会修改输入库；结果仅保留作用域指纹，避免暴露项目路径。模型 adapter 由使用者提供，真实调用必须另行配置预算。

工具激活评测要求实际目标执行加正确最终答案。无效 JSON 会整段拒绝，不执行首个看似合法的片段；有界错误原文与明确拒绝原因帮助下一轮纠正，超长内容只记录摘要。推理完成与动作被拒分别记账。代码安全、权限、请求步数和冻结约束继续生效，新源码指纹不能继承旧冻结结果。

已有隔离验证完成“真实文件失败与恢复→事件入队→模型提炼→契约验证→新目标召回→模型实际修改→最终确认”，并验证历史错误后的纠正。但它不是任意环境的上线承诺，也不能证明经验带来的因果收益、未知错误泛化或长期改善；真实部署应独立核对已加载版本、权限和数据保留。
