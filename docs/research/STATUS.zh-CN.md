# 实现与部署状态

本页先列当前 RC2 状态，下方既有实验与部署记录为历史证据。源码、隔离测试、模型行为确认、运行接入和远端发布分别核对；部署者自建实例不自动继承维护者的结论。

## 当前 RC2 更新

适配 Harness RC2，更新工具契约与前向维护流程，并验证任务执行、状态更新及跨会话记忆复用。

当前 SDK 基线为 `0.2.1-rc.2`，兼容补丁按该版本原始文件摘要生成，保留结果重新校验和能力可用性过滤；不复制旧版宿主中已由官方提供的机制。补丁与运行文件契约一致，插件核心记忆算法没有因本轮更新而改变。

在已部署的 RC2 宿主完成三个真实任务轮次：创建任务清单、更新任务状态、新会话复用同项目合成偏好。任务文件实际读回，新会话运行时上下文中的来源 ID 与回答引用一致；没有把模型自述当作采集或检索成功证据。具体模型配置、会话正文和运行路径不公开。

`frozen`、`propose-only`、`shadow-only` 边界保持；本轮未制造工具契约错误，不构成新候选晋级、长期收益或所有外部供应商可用的证明。工作目录限制是操作约束，不是操作系统强制沙箱。媒体插件不在本仓库收录范围。

当前源码门禁为 917 通过、0 失败、5 环境跳过；RC2 可选实际后端的流式检查 2/2、合同复现 5 个场景通过，详见[验证范围](../VALIDATION.md#rc2-同步检查)。

当前维护前向修复，不保留旧软件目录或自动回切；历史记录中的恢复步骤不作为当前安装流程。

## 失败、恢复与限制

首轮服务切换未通过健康检查，按计划恢复了本轮 MNEMO 源码、配置和守护清单。重新启动时暴露了既有宿主回收站的状态兼容问题：清除流程会写出 `purged`，启动校验却遗漏该合法状态。经隔离复现和独立复核后，宿主仅补上该状态校验；用户账本字节保持不变。随后在恢复健康的宿主上重新部署并完成上述验收。失败与回滚凭证保留，不覆盖为成功。此宿主恢复操作不属于本套插件的新增功能。

本次线上“恢复采集”使用新的用户输入；无新用户输入的续接、重复事件、撤回、配额、只读写锁和合同变化另有组件/实际后端 fixture 检查，不能冒称全部在线上逐项跑过。线上固定回答任务未制造工具错误，故不证明真实业务错误已经自动变成有效经验；候选生成及不可注入边界由独立测试验证。

完整架构中的一般机制提炼、覆盖优化、概率可靠度和统计推广仍是研究设计。当前是单一激活时序机制的采集与审查基础，不是完成了通用自主学习。

部署保留原源码、配置和守护清单备份；回滚不删除影子账本。文件采用原子替换，部署脚本不承诺断电事务或不可逆外部操作回滚。专用 `verify_changes` 工具在维护环境不可用；不提供该工具通过声明，替代发布门禁的批准与实际检查分别留痕。
