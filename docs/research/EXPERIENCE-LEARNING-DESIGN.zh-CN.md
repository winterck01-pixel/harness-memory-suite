# Harness 经验学习体系设计方案

日期：2026-10-17。状态：总体研究设计；其中工具激活时序的实验内核已实现，生产影子接入以[发布状态](STATUS.zh-CN.md)为准。本文的“建议”“应当”描述目标设计，不表示功能已经部署。自动行动注入、自动晋级和技能自动注册保持关闭。

请先阅读[研究导航与实现边界](README.md)及[首个切片的完整结果与失败](ACTIVATION-TIMING-PILOT.zh-CN.md)。

## 1. 结论与设计目标

建议在现有插件体系内建立一条完整的经验学习链：**持久事件 → 可追溯片段 → 有条件候选 → 局部验证 → 未见任务评估 → 限域经验 → 经测试的正式技能**。这不是再增加一个总结提示词，也不是把 trial 原文放进正常检索。

允许第一次做任务时探索、失败、修复。成功标准是：在后来条件相符的任务中，系统能识别以前已证伪的做法、知道替代办法及验证方式；条件不同或未知时能重新检查，而非机械重复旧经验。任务质量和当前授权优先，步骤、成本及缓存是后续优化指标。

底层模型通过 API 调用、权重保持不变。学习发生在外部证据、条件、检索策略、验证结果和程序资产上。因此这是一套外部经验学习系统，不承诺底层模型训练或通用自我进化。

建议先采用：**证据状态机 + 条件化案例推理 + 预算检索 + 冻结配对实验**。概率模型只作明确有假设的辅助；在线 bandit、端到端 RL、复杂潜变量模型留作后续研究选项。

## 2. 基线遗漏审查提供的实际约束

以下是提出方案时对基线实现的结构审查，不是对本文发布版本的实时缺陷清单。首个切片和后续接入逐项验收；下面区分确认的结构问题与尚未确定的现场因果。

| 已确认遗漏 | 框架设计响应 | 实施后的验收证据（尚未完成） |
|---|---|---|
| trial 写入后没有提炼消费者 | 持久工作项与消费回执，显式 episode→candidate 转换 | 合成片段产生对应候选；未验证候选仍不进入正常行动注入 |
| 捕获依赖轮末及本轮人类输入，恢复游标不足 | 从持久事件源消费，与有无人类续接解耦 | 重启/续接对账无静默缺口；确实缺证据则标 incomplete |
| trial 是助手文本，缺动作—错误—修复—验证关系 | 结构化事件与证据图，分离观察和归因 | 同轮失败与成功分别关联；不能从最终成功奖励整轮猜测 |
| 20 条/1000 字窗口与消费无协调 | 热窗口、原始证据保留、候选索引、注入分别预算 | 超窗口后未消费材料仍可处理，或明确报告来源缺失 |
| 声明采用到验证反馈未贯通 | 精确版本收据→动作关联→独立验证队列 | 声明不强化；有验证依据才更新对应候选 |
| applicability 写入和任务特征未端到端连接 | 持久化前提、可信任务特征、三值判断 | match/mismatch/unknown 在写入、检索、注入和评估一致 |
| 现有问答评估不能证明实际少走旧弯路 | 未见真实工具任务、分组留出、质量与复发联合验收 | 复发下降且任务质量非劣，边界任务无错误采用 |
| MNEMO skill 记忆不是 Registry 技能 | 流程候选→可执行测试→受控发布的独立出口 | 真正可加载、可运行、可撤回的技能版本 |

真实会话的若干结果缺口与捕获风险相符，但各轮缺失的精确原因并未全部证明。本方案不把它们归为同一已确认进程故障。旧 checkpoint/原始日志可能保留退出热窗口的信息，也不宣称它们已永久丢失。

保留现有有效机制：项目隔离、当前用户授权、整轮禁用/撤回、trial 隔离、来源和版本约束、曝光与声明分账、候选专属评估、回滚、propose-only/frozen。已有组件测试通过不等于整条学习链有效。

## 3. 论文研究如何影响选型

三条研究线分别覆盖神经/认知机制、代理记忆与技能、数学与实验设计。论文用于提出约束和可检验假设，不把跨领域类比当效果证明。

| 研究依据 | 可借鉴之处 | 不应据此推导 |
|---|---|---|
| 互补学习系统 [1]；schema 实验 [2] | 具体经历与跨经历概括分层，概括保留条件 | 外部文本存储等同人脑；一次相似案例即可形成通用真理 |
| 优先记忆访问模型 [3]；上下文/潜在原因模型 [4] | 按未来决策价值复盘，条件变化保留分支 | 检索频率就是可信度；聚类结果就是已识别原因 |
| Reflexion [5]、ExpeL [6] | 外部反馈、失败—成功对比有研究基础 | 自我反思或票数可以代替独立验证；同题重试就是跨任务迁移 |
| Voyager [7] | 技能应有实际可执行资产与测试 | 环境中的技能成功可直接保证生产编码安全 |
| A-MEM [8]、ACE [9] | 原子条目、关联、增量更新可作为组织方法 | 链接即因果；反复整库改写不会损失信息 |
| 持续更新记忆退化研究 [10] | 必须保留 episodic-only 对照，检验条件丢失和干扰 | 所有抽象都无效，或论文某一模型结果适用于所有模型 |
| MINJA [11] | 记忆写入也是攻击面，模型总结不能洗白来源 | 仅靠一条提示词即可阻断所有记忆投毒 |
| MillWheel [12] | 故障恢复需持久状态、处理位置及幂等设计 | 外部部署/删除等现实副作用可被“恰好一次”保证 |
| SWE-agent [13]、SWE-bench [14] | 工具接口和反馈质量重要；真实产物验收必要 | 历史 benchmark 排名等于本项目效果，或统一截断长度适合所有工具 |
| 因果推断、统计与优化研究 [15–22] | 明确干预目标、独立单位、约束、估计假设 | 任意旧日志可以无偏评估新策略；一个置信分数能解决全部问题 |

[10] 是新预印本，其不同位置的部分数值表述不一致，本文不引用其效果百分比；它提供应专门验证的失败模式。神经科学中部分证据来自动物实验、理论模型，不能直接证明 LLM 记忆机制有效。新代理论文也需在本项目复现，而非按“顶尖”标签直接采用。

## 4. 统一框架：事实、知识、执行、治理四条责任线

```text
宿主持久会话/工具事件
       │ 幂等摄取、游标、缺口检查
       ▼
事件证据层 ──→ 任务/尝试片段 ──→ 候选提炼与反例关联
       │                            │
       │ 来源、版本、撤回             ▼
       └──────────────────→ 局部验证与冻结评估
                                    │
                          有条件经验/程序候选
                              │           │
                     条件检索/上下文投影  技能测试与受控注册
                              │           │
                              └────┬──────┘
                                   ▼
                            后续真实任务执行
                                   │
                          观察、采用、验证分账
                                   └──→ 新证据/冲突/再验证

治理约束贯穿全程：授权、隔离、来源、禁用、预算、隐私删除、冻结、撤回。
```

采用一个逻辑证据账本和派生视图，不再让任务账本、记忆、知识库、技能库分别猜测“发生了什么”。逻辑统一不要求把所有原始字节复制到一张表；原始事件源可保留在宿主，学习层保存稳定引用、指纹和必要的脱敏结构。

当前用户指令、授权、规则属于治理输入；经验属于可质疑的建议。**高统计收益不能提升权限，旧经验不能覆盖当前指令。** 未经验证的来源内容不能成为规则，即使被总结过多次。

会话、任务和尝试不是同一个单位：同一目标的重启续接保持 task 身份；用户明确更换目标时建立新任务边界，并引用前任务而非混合成同一成功/失败样本。归属不明先标待关联，不能猜测后用来强化经验。采集前先应用既有学习禁用、范围与隐私策略；宿主为交付任务保存的会话日志不自动等于允许进入学习账本。

### 4.1 事件证据层

建议最小字段：

| 对象 | 关键字段 |
|---|---|
| Event | eventId、源序号、session/task/attempt ID、类型、父事件、时间、来源摘要、schema 版本 |
| Action | 工具调用 ID、工具契约指纹、脱敏参数/产物引用、调用前环境与权限版本 |
| Result | 工具传输状态、工具业务状态、可观测子进程退出状态、stderr/产物引用、完整/缺失/截断标记 |
| Verification | 被验证的主张、验证器版本、对应状态/产物指纹、通过/失败/未知、覆盖范围 |
| Context | 可信项目标识、工作区版本、依赖/工具/运行环境已观测特征、未知字段 |

不保存模型隐藏思维链。只使用可见决策说明、真实操作、外部结果与可审计的验证。

工具“调用成功”不等于业务操作成功，业务成功也不等于目标完成。对于 run_code 等复合工具，优先建立标准结构化子结果契约；内部不可观察时保留 partial，不能靠错误字符串正则虚构完整因果链。

### 4.2 故障恢复协议

1. 以宿主持久源序号为准消费，不能依赖本轮是否出现 human 文本。
2. 幂等键包含源身份、事件序号、事件类型；内容指纹用于检测同序号不同内容的冲突。冲突隔离而非静默覆盖。
3. 在同一事务中提交派生状态、待处理工作项和消费位置。若跨存储不能事务提交，采用可恢复 outbox 和幂等投影，明确一致性边界。
4. 重启后从持久位置回放，检查缺号、乱序、迟到、未完成调用和重复结果；等待窗口到期仍缺结果则标 unknown/incomplete。
5. 回放的是**学习观察**，不会重跑部署、重启、删除、支付等原操作。
6. 提炼工作项由来源集合指纹、提炼器版本及策略版本确定身份；失败重试、死信与积压可见。重试不得制造多份独立经验。

需要先验证宿主持久事件源是否完整暴露工具结果及恢复标识。若不支持，先补宿主观测契约；仅在插件末端再加一次 turn-end 回调不足以解决源头丢失。

### 4.3 四种记忆对象，采用不同用途

| 层 | 含义 | 允许用途 |
|---|---|---|
| Episode：具体片段 | 在某条件下做过哪些操作，观察到什么 | 来源检查、受限案例检索、候选生成；不能伪装成通用命令 |
| Candidate：条件候选 | 一项待验证解释/修复建议，带前提和反例 | 复盘、沙箱验证；正常行动注入默认关闭 |
| Lesson：限域经验 | 在明确条件和证据范围内可复用的经验 | 条件匹配后进入受预算的正常检索 |
| Procedure/Skill：程序资产 | 契约、步骤、分支、验证、退出与恢复齐备 | 通过技能生命周期审核后才能进入宿主 Registry |

经验生命周期建议：captured → proposed → locally-reproduced → heldout-evaluated → scoped-active。流程候选再经 compiled → tested → approved → registered。任一阶段可进入 quarantined、needs-revalidation、withdrawn。

这是证据状态，不是权限状态。不同来源等级和当前授权另设轴线。单次可信失败可支持“这个具体案例发生过”及限定的检查建议，不足以变为跨项目自动执行规范。对高代价边界可先设人工审核的诊断提醒，而不是等待大量事故或自动提升为全局技能。

`heldout-evaluated` 不表示通过；进入 `scoped-active` 还须确认实验通过、来源/版本有效、适用范围获准、冻结策略允许。当前 frozen 不因完成研究或实验而自动改变。正式 Registry 注册另受技能发布守卫约束。

## 5. 从片段到经验的算法

### 5.1 分段与证据图

按 task/attempt、操作对象、错误机制和验证状态分段，而非整轮 failed 就把所有助手文本当失败。

证据图保存：observed-before、invoked、returned、verified、contradicts、supersedes，以及单独的 hypothesized-repair 关系。时间先后不等于因果。

一个候选至少有：

```text
主张；目标/问题类型；适用前提；禁用/失效条件；未知条件如何检查；
失败签名；已观察到的无效动作；修复假设/替代步骤；验证器；
来源与依赖组；局部/迁移证据等级；反例；版本；缺失与不确定性。
```

失败前后多项环境同时改变时，保存“组合修复候选”，不能把成功平均归功于每一个改动。要识别单项机制，需做局部控制变量重放/消融。最终任务成功只证明终局验收通过，不会令全部中间假设变真。

### 5.2 条件化聚合与提炼

先用工具契约、错误机制、目标与环境边界作硬分组，再用语义相似度找可能相关片段。相同措辞不等于相同原因；同一根因的多次重试不是多个独立样本。

提炼触发：一个失败—修复片段闭合、外部验证到达、用户纠正、出现独立相关案例、反例或版本漂移，以及保留压力。进度广播和每个 turn 不自动调用模型反思。

提炼器只提出结构化增量；检查器验证引用存在、引用确实支持主张、关键条件没有被删、反例没有被吞、来源权威没有升级。只修改受影响条目并形成新版本，避免每次重写整库或只拿摘要继续摘要。可拒绝提炼，保留具体案例。

### 5.3 使用与反馈

分别记录：检索候选、实际展示、模型声明采用、可追溯动作关联、外部验证、受控干预效果。

使用声明用于寻找应复核的候选版本，不增加成功数；动作关联也只证明有关联。外部验证能确认产物或断言，而候选是否提高后来表现由配对实验估计。

反馈含正例、反例、未知。条件变化优先新建分支或待复核；不把新版本的失败粗暴用于推翻旧条件下成立的事实。不因当前没有被用到就降低主张真值。

### 5.4 反例、保留与删除

区分原始证据保留、待处理队列、活跃索引和提示词注入四个预算。现有 20 条窗口可作为兼容的热视图，但不能继续充当唯一学习源。

未经消费的关键片段需有持久引用及消费回执。来源达到保留期限、配额耗尽或原始宿主删除时，显示缺口并禁止依赖缺失证据晋级；不能无限积压，也不能声称已沉淀。先淘汰重复进度和可重建索引，反例、罕见高代价失败保留独立配额。

“证据不可随意改写”服从隐私删除及禁用要求：删除或撤回需立即阻断召回/晋级，并清理派生索引、候选引用、嵌入、提示词材料及缓存；备份清除按实际保留能力和已告知期限处理。只在允许的情况下保留不含内容的最小撤回标记，不能借审计名义永久保存私密原文。

删除必须沿来源依赖图使全部后代失效，包括混合来源摘要、经验卡、旧版本和已注册技能中的派生内容；不能只删除引用而留下私密事实。若仍有合法独立来源，仅用剩余材料重新生成并重新验证，不能原地去掉来源标签后继续用。恢复备份、重建索引和加载技能时重新应用撤回清单，防止旧内容复活。

已经发送给模型的上下文无法承诺即时擦除：停止后续注入、工具传播和持久化，在下一安全边界重建上下文；供应商侧删除遵循实际接口与保留能力。普通学习禁用阻断其范围内读取、写入及回补，不自动等于销毁既存记录；来源撤回使派生使用资格失效；隐私删除才执行上述内容清除链，三者分别记账。

关键来源过期、产物不可访问或完整性无法确认时，既有 Lesson/Skill 也要重新检查支持依赖。若没有仍有效的独立支持与验证凭据，则转 needs-revalidation，暂停行动注入/加载；若仍有充分独立证据，则记录新的支持集和范围。允许按类别保留脱敏片段、指纹与验证凭据，但须明确因此失去的可复核能力，不把“完整”理解成永久保存全部原文。

## 6. 数学模型与选择理由

下面是本项目的工程模型，不宣称是论文原定理的直接应用。三值条件判断已在首个实验切片实现；覆盖优化、Beta 后验、价值调度和统计晋级门槛为拟议方法，未拟合参数，也没有据此取得线上收益结果。

### 6.1 总体：固定模型上的条件案例策略

记底层模型为 πθ，θ 不变；η 表示外部记忆版本、检索配置与已验证程序。实际代理策略写作：

    μη(a | h) = πθ(a | Project(h, Retrieveη(x(h))))

h 是已获授权的可观察任务历史，x(h) 是当前可观察特征，Project 是有预算的工作上下文投影，a 是下一动作。η 的更新必须经证据与评估，不对 θ 做训练。

这个模型明确了优化对象：形成什么经验、何时能用、展示哪些、如何保持当前任务信息，而非虚构底层模型已经通过文字反思更新参数。

### 6.2 适用性：三值约束先于相似度

对候选 i 的必需前提集合 Pi，用可信观测 x 判断：

    gi(x) = mismatch  若任一必需前提被证伪
            match     若全部必需前提已观测且成立
            unknown   其余情况

另外独立检查权限、来源撤回、项目范围、证据状态和版本。只有这些硬条件都满足且 gi=match，经验才可成为行动指导。unknown 只产生最小事实检查建议；不能核实则退回正常推理，继续用户任务。mismatch 不作为行动规则注入。

不能从助手总结推断权限或把未来验收结果作为行动前特征。一般机制可以有显式审核的跨项目适用域，项目私有事实仍留在项目内。

### 6.3 检索：硬过滤后，选择覆盖且不过度重复的经验

检索流程：精确错误/工具契约/版本与文本检索 → 可选语义召回 → 硬过滤 → 去重与冲突/依赖检查 → 预算选择。

令 I(x) 为可用候选，S 为选择集合，u 为当前任务需要覆盖的机制、前提检查或验证要点：

    F(S | x) = Σu wu · max{i∈S} aiu，约定空集最大值为 0
    S ⊆ I(x)，Σi∈S tokenCosti ≤ B

wu≥0 是预先定义的要点权重，aiu∈[0,1] 是可审查的覆盖评分，不解释为成功概率。额外约束包括数量、来源多样性、版本互斥、冲突、程序依赖闭包。完整程序依赖可打包后再选，防止仅保留最后一个关键命令。

该覆盖函数本身单调且有边际递减，但真实效用未必如此。对带 token 背包、冲突和依赖的选择器，普通收益/成本贪心不自动拥有 1−1/e 保证 [22]。第一版比较 top-k、覆盖启发式、小候选集枚举；用真实任务结果决定复杂算法是否值得。

沿用现有阶段预算作为迁移起点：最多 24 个展开工具、2 项技能、5 个知识片段；经验卡片如何计入当前上下文总额必须显式定义，不能另开不受控通道。若经验预算不足，省略经验或保留完整的小程序包，不强停用户任务。

### 6.4 可信度：分量表示，拒绝一个万能分数

分别展示来源、捕获完整性、前提满足状态、主张的验证证据、干预收益和漂移状态。曝光、采用、自评与成功不同，不能混成一个置信度。

仅在同质、近独立、外部标注的二元验证条件下，可附辅助模型：

    p ~ Beta(a,b)
    p | data ~ Beta(a+s,b+f)

s/f 为明确试验分布中成功/失败数；未知不填成二元结果，另报未知数及总分母。若未知依赖策略或结果，后验只描述可评价子集，不能代表总体成功率或支持晋级，需作保守缺失敏感性分析。重复源需按依赖组处理，不能重复计数；不能任意把一个异质依赖组压成一次 Bernoulli。该后验描述试验成功率，不是主张真值或因果收益；先验敏感性必须可见，不作为单独晋级开关。

数据达到多项目、多机制、独立重复组后，再比较分层 logistic 模型：

    logit P(z=1 | i,x,g) = θi + βᵀx + uproject + umechanism + usource

它需要可交换性、模型设定与可识别条件；少数组时容易先验主导，不能自动去除混杂。当前不以它增加复杂度。

### 6.5 复盘调度：价值驱动，但不捏造 Gain

借鉴 gain×need 的思想 [3]，候选工作项价值可写作：

    Ui ≈ Needi × Gaini − Costi − Harmi

Need 是未来条件相符的机会估计，Gain 是经过评估的潜在决策改善，Cost 是提炼/验证开销，Harm 是误用代价。未经测量时标未知，不能用模型自评信心替代。

第一版不用虚假精确值求最优：按“证据缺口/撤回优先、独立失败—修复、用户纠正、反例、高代价稀有机制、普通整理”分层调度，并为冷门机制保留检查预算。调度优先级不是可信度，严重性也不自动带来晋级资格。后期有数据再比较价值排序与简单队列，记录抽样概率。

撤回即时生效，不排在普通提炼队列里等待。普通队列设分层保底预算和等待时间提升，避免长期饥饿；容量、最大等待及重试上限显式配置。超限暂停新增提炼、保留最小合法引用与缺口状态，不挤占正常任务资源，也不声称所有原文均已保留。

### 6.6 因果目标：验证记忆干预，而非奖励整条轨迹

对预声明机会集合中的任务 i，A 为冻结基线，B 为增加指定候选版本/策略。Q 是独立验收质量，R 是该机制是否复发：

    ΔR = E[RA − RB]       正值代表减少复发
    ΔQ = E[QB − QA]       正值代表质量改善

优化采用词典序：先满足权限、来源等硬约束及质量非劣，再考虑复发改善，最后比较成本/延迟。不能用节省 token 抵消越权或质量下降。

建议晋级判据形式：

    LCB(ΔQ) ≥ −εQ
    LCB(ΔR) ≥ δR
    边界探针、来源、授权、版本与撤回检查全部通过

LCB 为预声明统计方案下的下置信界；εQ 是允许的质量非劣界，δR 是最小有意义改善，均在确认实验前依据风险与功效设计确定。以上是决策协议，不是黑箱模型安全的数学保证。未观察到严重事故不能证明风险为零。

配对干预可估计“展示该经验/采用该策略”的总效果，不能仅凭这个结果宣称某条中间动作是唯一原因。单项修复因果需要另外的控制变量实验 [15]。

明确区分两种干预单位：单候选增量评估才支持该候选版本的晋级；整套检索/提炼策略的 B−A 只支持对应冻结组合，不能给组合内每张经验批量记成功。若单项效应不能分离，只能作为一个限域组合评估和发布。沙箱效应外推到生产还需运行合同、权限、反馈与任务条件可迁移，不能自动等同线上收益。

### 6.7 当前不直接采用的模型

| 方法 | 暂缓理由 | 何时重新考虑 |
|---|---|---|
| contextual bandit / IPW / CRM [16–17] | 现有确定性日志缺已知选择概率和未选动作支持；多步依赖强 | 有安全随机化日志、已知倾向、支持覆盖和可信反馈 |
| Conformal / RCPS [18–19] | 稀疏且漂移数据不足以提供所需校准条件 | 独立校准集、明确损失与分布条件齐备；仍不解释为单条真值保证 |
| 持续置信序列 [20] | 不能修复任意相关与环境漂移 | 任务组抽样与条件期望假设可说明，且确有持续查看需求 |
| CPO/底层模型强化学习 [21] | API-only 缺动作分布、权重训练接口及受控奖励 | 后续单独训练研究，不能借用其约束保证 |
| 模拟海马/潜在原因神经模型 | 当前可观察条件和数据量不足 | 简单条件模型显著受限且有足够受控数据时做对照 |

## 7. 验证设计：证明以后不再重复旧弯路

### 7.1 “弯路”要事先定义

复发是：在已观测到相同适用条件时，再次执行已被可信证据证伪、又没有新检查目的的同机制无效做法。新条件下的合理探索、验证旧假设是否失效、提供新信息的只读诊断不算同一种失败。

不能用“报错数量”替代：故意触发一个预期错误有时正是正确测试。也不能让提前失败、少调用工具的代理因复发少而获胜，必须联合验收质量。

衡量 R 时，以处理前固定的环境真值、错误机会和盲判规则为准，不依赖代理在某一处理臂是否恰好观察到了条件，也不接受“我是在探索”的自报豁免。新信息检查须有预声明的可观察判据。条件或动作意图无法可靠判定时记 NA 并做缺失分析，不能记成未复发。经验的运行时三值判断仍使用代理当时实际能观察的信息，这与评估的独立真值分开。

### 7.2 基线与消融

按阶段比较，控制实验开销：

1. A：冻结当前体系，作为部署基线。
2. B：相同完整观测与工具反馈下，仅增加具体案例检索，**不跨案例概括**。
3. C：B 的同一来源材料，加条件化提炼；检验抽象是否真的优于案例。
4. D：C 加预算覆盖排序；验证是否比简单 top-k 更好。
5. E：通过前述评估的流程加入技能注册；再检验技能增量。

若补工具反馈或采集包装器，所有比较臂使用相同版本。接口改善的收益不能误报为记忆算法收益。episodic-only 不是把全历史塞进 prompt，而是在相同注入预算下取完整、可追溯的有限案例。

因此保留原部署 A0 作整体变化参照；更新共同测量/工具合同后的 A1 才是记忆增量实验基线。A1−A0 与 B−A1 分别报告。

另设诊断臂 N：保留用户规则、授权、当前任务事实和相同工具合同，关闭模型派生历史经验，用于检查整个经验通道是否负迁移。它不替代单候选增量评估，也不把安全规则一并关闭。

### 7.3 数据划分和任务内容

先按源会话/bug 根因/衍生补丁/项目版本建立依赖组，再划分来源提炼集、开发集、校准集和锁定确认集。同题改写、同一轨迹重放、不同随机种子不能冒充多个独立迁移任务。跨项目声明需整项目留出。

工具任务至少包括：真实作用域/运行上下文差异，工具发现与激活契约，工具传输成功但业务失败，重启续接，产物与运行实例不一致，版本变更、前提未知、相似措辞不同机制、跨项目冲突和恶意来源。使用脱敏沙箱，现实危险副作用使用模拟器；不能为评估重新删除真实文件或重启生产。

每个任务预定义目标产物、验收器、错误机制、是否有该错误机会、允许工具和中断规则。最终产物/构建/行为验证为主，模型评审仅辅助，争议样本人工复核。确认集不能参与提炼或阈值调整；修改候选后消耗新的确认数据。

### 7.4 执行及统计协议

- 固定候选、来源指纹、检索策略、模型路由/版本、环境快照、初始缓存与验收器；两个独立沙箱随机执行顺序。种子只帮助复核，不保证轨迹同随机。
- 在处理前固定机会集合，报告任务级复发及重复次数；不用处理后改变的机会数作唯一分母。
- 所有分配任务纳入分析；超时、取消、缺失、源故障单列并做敏感性分析，不只挑双方成功任务。
- 按依赖组汇总差值；组数足够且条件适合时用按组重采样区间。少数组展示逐组结果和保守推断，不把工具步骤当独立样本。
- 预先选择按独立组等权、按任务等权或按目标部署分布加权，并明确对应目标总体；不在看到结果后挑有利权重。
- 第一版预注册固定终点，不边看普通 p 值边择机晋级。多个候选/确认检验预分配误差预算，Σαk≤α；后续顺序方法另行满足其假设。
- 样本量由基线复发、最小改善、配对相关、组数、分层和多重比较设计。已有样本下限继续保留，但不能把“60 条”或“90%”等阈值当普适统计证明；不足就保持 frozen。

主要报告：ΔQ、ΔR、边界错误采用、unknown 处置、无关任务负迁移、独立组数及区间。其次报告无效调用、token、延迟、存储、提炼费用和实际计费。检索命中、采用次数、缓存率只是诊断。

### 7.5 系统可靠性与反污染测试

单独覆盖：提交前/后崩溃、重复/乱序/迟到事件、同序号内容冲突、无人类续接、缺工具结果、复合工具失败、超热窗口、积压/配额、撤回并发、隐私删除派生清理、摘要丢条件、来源洗白、同源重复计数、程序缺前提、旧技能仍被缓存加载。

捕获层验收是“在明确测试源事件范围内逐条可对账，缺口明确”，不是笼统宣称所有未来事件零丢失。学习层验收是后续行为改善，不能用系统测试数量替代。

这些是责任边界，不要求新建同等数量的服务。第一版可复用当前存储和维护器扩展内部记录类型，避免平行造一套工作流。

知识文档说明“是什么”，经验说明“什么条件下遇到过、怎么验证”，技能说明“如何按契约执行”。三者可引用同一证据，不能相互提升权限。

### 8.1 历史和缓存

证据保存与模型工作上下文分离。历史投影保留当前目标、限制、已确认事实、关键错误、当前产物版本、待验证点；冗长旧输出变为有权限的产物引用，需要时局部读取。不能丢失错误 stderr、程序前提或反例来换取短 prompt。

尽可能稳定核心指令、工具顺序及阶段内定义，把变化的经验卡放在动态部分；但工具变化、来源撤回和版本更新仍可能影响缓存。缓存不是最终目标：比较同任务质量下的实际总费用与延迟，并读取供应商原始 cached usage。不能凭 UI 命中率或协议名称推断原因。

### 8.2 技能形成

正式程序需明确输入/输出、环境/权限、步骤分支、错误处理、验证、退出和恢复；凭据只能运行时注入，不能写进经验或技能。先沙箱测试有效与失效条件，再走现有技能审核/注册流程。加载记录绑定技能指纹，升级/撤回使旧加载材料失效。

候选生成可后台自动化；正式技能发布和自动晋级继续服从既有治理。当前没有理由因新设计而解冻，也不增加“每做一次任务重新连接”的手动流程。

记忆片段作为带来源的数据封装，不以 system 指令拼接；提炼和检索不赋予工具执行权。结构化卡片、内容转义和模型提示只是防线之一，宿主仍独立执行权限/工具可用性检查。工具发现、激活应读实际版本合同，复用连接与已验证能力目录；经验可提示查询哪项能力，不能伪造可用工具或凭旧流程绕开激活。来源不可信的命令、外部文档和模型自述保持污染标签，不能通过总结升级身份。

运行观测至少包括：事件覆盖/缺口、消费延迟、提炼积压/死信、来源撤回传播、unknown 比例、条件误用、候选/技能版本、各阶段预算与失败降级。共享现有宿主生命周期和连接，持久化必要状态；学习预算耗尽退回正常任务，故障状态可见，不宣称仍在成功学习。

| E 限域试点 | 独立决定试点范围与发布，绑定经验/策略版本 | 当前授权内行为可复核，可一键撤回对应经验策略 |
| F 程序化技能 | 已验证重复流程编译、测试、审核、注册 | Registry 真加载、真执行、版本和撤回端到端通过 |

先以兼容扩展和影子读取迁移，不删旧实现或旧数据。旧 trial 只导入为来源不完整的历史片段；有授权且原始源还在时才回补。用户规则、人类确认事实保留原有身份，不重新当模型猜测。禁止在禁用或撤回的材料上追补学习。

策略版本可独立回滚至当前基线；保留可读取的旧 schema 与导出，迁移步骤可重入。候选/索引重建不改原事实。回滚不是撤销真实任务的文件操作，任务操作恢复仍由原工具流程负责。若某功能失败，只关闭新增学习消费者或检索策略，不让后台学习故障阻断正常任务。

实施前需核实的工程事实：宿主事件源的持久边界与结果粒度、项目/task 稳定标识、当前存储事务能力、SDK 结构化结果可扩展面、上下文预算的实际共同计数、Registry 版本撤回能力、用于沙箱的合法脱敏任务来源。这些不是已完成能力。

第一版只选一种可复现工具契约错误，跑通持久事件→片段→条件候选→人工审查→冻结对照这一条垂直链；同时覆盖其重启、缺失、撤回边界。覆盖优化、分层概率模型和正式技能编译不作为首个切片的必要依赖；待这个切片证明有用后逐项展开，避免在数据不足时把全部研究模型一次性实现。

## 10. 一个完整工作例子

以下是合成示例，只借用作用域和工具激活两类问题说明机制，不是原会话的事实重建：某编码任务先在模拟环境自检通过，实际宿主运行却出现作用域错误；修复上下文绑定后真实执行成功。同轮还有工具激活参数错误。

1. 保存两类错误各自的调用、契约和结果；工具激活错误不会因为同轮最终成功而被记作有效步骤。
2. 建立案例：模拟器和宿主的上下文合同不同；局部补丁后通过指定真实路径验证。若同时改动多项，则标组合修复，机制未单独确认。
3. 提出有条件候选：在该上下文合同下，mock 测试不足以覆盖真实回调边界；先核查宿主合同，再运行对应路径测试。不能概括成“所有 mock 都没用”。
4. 工具激活另形成契约候选，先核实实际可用参数，不把某次参数格式推广到所有工具版本。
5. 新任务条件吻合才展示相应卡片；版本未知先只读查询合同；不同环境不套用旧补丁。
6. 在未见任务中比较具体案例、条件经验和现有基线。如果没有减少相同错误，收窄/撤回，不继续积累自我赞同次数。
7. 多次独立验证的流程才可能成为正式技能，包含失败分支与真实运行路径验收。

这条路径允许首次试错，但要求每次“学到了”都有来源、范围、验证和撤回能力。

## 11. 方案的可证伪预测及局限

- 完整事件消费应修复审查发现的中断与 trial 无消费者问题；若源头事件不存在，则必须报告观测不足，插件不能凭空恢复。
- 条件案例应比整轮总结更少误用；若三值检查使覆盖过低而无质量收益，应调整可观测特征和检查成本，而非把 unknown 当 match。
- 提炼经验应在相同预算下优于具体案例；若没有改善，保留案例作为主路径，不为抽象而抽象。
- 预算覆盖选择应优于简单 top-k；若收益不足以抵消开销，使用简单方案。
- 技能注册应在已有经验之上进一步改善真实执行；若只是增加文件数量，技能学习不算成立。

方案仍依赖工具反馈质量、可获得的验证器、模型遵循程度和任务分布。它不能保证以后所有同类错误都消失，也不能靠统计实验放弃宿主权限强制。具体阈值、资源限额、样本量和排期应在 A 阶段基线测量后确定；本研究不编造已拟合参数或交付天数。
