# 主动经验复用的已知缺口

当前目标是让 Agent 从已核验的成功方法中找到适用做法，并在类似任务中少走弯路。源码已接通条件卡片、真实来源、检索、采用和后续结果反馈；这不等于含糊目标下的通用自主复用已经完成。

在此前两轮真实任务中，第一轮能够完成任务并保存有来源的成功方法；新会话的含糊任务也能完成，但主要读取了旧产物，没有召回和采用先前经验卡。后续经验登记尝试还出现参数交互错误。因此，任务完成能力、保存能力、实际检索采用与业务质量必须分别判断。

|缺口|当前限制|后续方案应回答的问题|
|---|---|---|
|查询线索不足|自动检索主要依赖用户原句；读到新事实后没有自动补充查询再检索|如何获得有效线索，同时控制误召回与上下文增长？|
|工具参数交互不足|部分 PTC 可见参数类型与错误提示不够明确，可能导致重复猜格式|如何让声明、模型可见参数和运行校验一致，并提供可直接修正的反馈？|
|衔接依赖模型选择|提炼、检索、采用、结果反馈仍可能被绕过|在哪些有价值的任务节点接入，而不强迫每轮完成形式化流程？|
|真实来源不等于正确建议|旧资料中未经充分核验的建议仍可能被复制|如何区分检查过的方法、历史建议与当前约束，并发现冲突？|
|可选登记可能扩大排查范围|登记失败可能让 Agent 偏离主要任务去调查宿主|如何限定恢复范围，不能解决时及时结束可选登记？|

这些后续改进处于**暂缓状态**。本次源码同步没有降低召回阈值、追加开放式模型试验或宣称修复了上述缺口；也不新增发布或日常操作门禁。

重新评估需要有针对性的论文或成熟实现，说明它解决哪条缺口、如何适配届时宿主接口、额外调用与上下文成本，以及用少量真实任务即可判断的验收标准。公开仓库保留问题描述与适用边界，不包含私有任务原文、运行路径、模型路由或会话记录。
