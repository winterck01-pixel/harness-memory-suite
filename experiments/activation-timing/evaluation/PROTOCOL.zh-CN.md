# 工具激活时序：冻结配对小样本协议 v1

本实验只验证一个固定候选的增量效果。真实宿主为项目固定版本的 ToolRuntime、context-policy 和官方 JavaScript runtime；无文件、网络、部署等业务副作用的本地工具返回固定状态。此工具体属于实验夹具，工具绑定和激活机制属于真实宿主。禁止将确定性代理脚本的通过率表述为模型学习效果。

## 阶段和审批

1. source：从来源轨迹采集候选；development：仅 dev-01 可用于调试。
2. agent review：独立代理核对来源和条件。代理审查不能生成 humanApproved=true。
3. pre-human diagnostic：仅 development，可检查采集与模型回路，标记 diagnosticOnly。
4. post-human heldout：必须存在绑定候选内容、版本、审查包与协议摘要的真实人工批准，再执行锁定 heldout。
5. 测试不会自动促进候选、解除全局 frozen、增加 reinforcement 或生产注入。

## 对照和隔离

8 个任务，4 个任务族，每族2变体：未激活匹配、已激活、权限禁止、合同元数据未知。后两变体共享机制，不算独立机制样本。合同未知组只是隐藏实验元数据，真实宿主仍为 next-step；不得声称测试了其他宿主合同。立即生效及其他合同仅进行检索策略不适用测试。

每个任务建立两个独立新宿主：baseline 没有该候选；candidate 仅多出冻结候选卡。固定同一模型和路由、系统指令和每步真实宿主提示（包括原生的下一步激活说明）、工具初态、每次输出上限、6次模型请求预算；工具能力不因实验臂改变。模型可以生成白名单内 run_code 主体（无循环、动态成员、文件、网络、导入、原型访问），拒绝不安全代码计入已分配失败，不在后台重试；限制同时适用于两臂。它仍然，可以在同一调用激活后立即使用；runner 不内置激活策略。固定伪随机顺序交错运行每对两臂。禁止根据结果修改候选、提示词、任务或额外重跑挑优。

冻结清单包括候选、检索决策、任务、系统指令、runner、host、pipeline、协议、模型路由身份的摘要和全部任务顺序。模型身份与凭据在私有运行层保存；公共代码不含模型名称、服务路径或密钥。每臂全新对话；已完成任务的轨迹不喂给后续任务。

## 观测与判定

主要质量 Q：非禁止任务，真实目标工具执行并返回预定状态，最终回答包含状态；禁止任务，目标调用次数为0且明确报告权限不足。最终文本声明不能代替真实工具事件。权限允许的技术调用失败与权限禁止分开计数。

主要时序错误 R：预注册的 matching 任务中，在激活未生效的同一 runtime 步调用目标并出现不可用。重复错误 R_repeat：已经收到同一步绑定失败反馈后再次重复相同机制。首次错误和重复错误都报告。所有族分别列出，不用成功子集重新计算分母。

辅助指标：目标错误调用、重复激活、总模型请求、实际 usage、完成原因、transport/parse/runtime失败、目标输出、候选曝光和应用判定。不把缓存命中、字数、检索次数或模型自述当作学习效果。

所有预分配实验臂都进入 ITT 结果。请求失败、超预算、中止和未开始均保留；不自动重试，不把它们删除或算成功。实际宿主故障与代理任务失败分别报告，并对缺失结果给出上下界。调用预算耗尽仅表示实验臂未完成，不是生产任务的强制停止政策。

## 解释边界

这是机制 pilot，只有1个错误机制、4个测试分层，不能用16臂数或模型步数声称充分统计样本，也不足以通过现有推广门槛。报告逐对差异和每族原始结果；不使用小样本显著性或精确置信概率制造确定性。若baseline没有错误，则只能说未测出收益。若candidate只在适用组改善但边界退化，则不予推广。即便全部通过，仍 frozen、evaluationOnly。

## 预算与终止

开发诊断最多2臂×6请求=12请求；heldout最多8任务×2臂×6请求=96请求。单请求上限由私有provider冻结（本轮私有执行层冻结为1800输出token），不自动切换模型，不隐式重试。凭据/路由/配额异常停止后续网络请求，未开始臂写入ITT。普通模型格式错误或工具错误保留原始观测，可在剩余预算内自行纠正。

人工凭证属于可信桌面会话入口的外部证明，必须包含实际用户消息ID、候选冻结hash、review packet hash、协议hash；runner仅校验绑定字段，不能验证任意调用者声称的身份。禁止从JSON自造凭证或将 agent review 冒充人工批准。

## 开发诊断修订 A1：纯序列化白名单

以下为 A1 开发时点的历史记录（后续 A2 结果见公开实验报告）：当时正式 heldout 尚未启动。development v1 两臂各1次请求均输出 `console.log(JSON.stringify(activation))`，被原白名单拒绝，属于实验 wrapper 限制，不是模型激活时序错误或候选负迁移。原冻结清单、响应及拒绝结果完整保留，不覆盖、不混入正式收益计算。

只增加 `JSON.stringify(value)` 单参数纯序列化，禁止 `JSON.parse`、其他 JSON 方法、动态成员、JSON 重绑定、函数 alias、replacer 回调及全局访问。相同修改用于两臂，仍允许同程序激活后立即调用，以真实宿主决定成败。SYSTEM 同步列明。重新冻结开发 v2，每臂最多5次请求：v1 2次加v2至多10次，共享开发上限12次，不扩大预算。修订不依据 heldout 结果，不修改候选及任务内容。

## 正式运行前的审查修订 A2

开发 v2 后独立审查修正了判定器：只接受真实失败状态、精确 TypeError 错误字段、程序AST中的目标调用与缺绑定快照，成功日志不计错误。清理失败仍落盘并保留全部分配臂，后续请求停止。AST检查覆盖全部原始代码，而非包装函数的首个函数体；发现的包装关闭输入在真实runtime中本来会是语法错误，未证明宿主逃逸。正式冻结另外保存实际runtime process.js等执行源码摘要、Node版本/二进制摘要、检索三值决策。候选、任务、预算和两臂提示语义不变；旧开发批按各自冻结记录解释，不覆盖或并入正式确认结果。
